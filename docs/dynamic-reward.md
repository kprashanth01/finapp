# Dynamic monthly selection reward (Issue 10)

`dynamic-selection-proxy-v1` scores which of the six existing advisory agents were selected for **one observed synthetic month**. It uses `DynamicPlanningState`, built from the seeded population and trajectory pipeline. This is a research objective, not money, financial improvement, or a validated measure of advice quality. The selected agents do not change the month's balances.

The existing `selection-proxy-v1` reward, saved-profile API, 16-feature observation, and committed DQN artifact remain unchanged. Their reported results cannot be compared numerically with this new proxy or attributed to it. A policy must be trained and evaluated against this reward separately before its dynamic performance can be reported.

## Rules and components

All conditions use the current month's observable data. `relevant_agents`, `critical_agents`, `missed_critical_agents`, `unneeded_agents`, and a per-input `checks` list accompany every score.

| Component | Exact calculation |
| --- | --- |
| `relevant_coverage` | +1 for each selected relevant agent |
| `critical_coverage` | +2 for each selected critical agent |
| `missed_critical_penalty` | −3 for each critical agent omitted |
| `unneeded_agent_penalty` | −0.75 for each selected agent outside the relevant set |
| `agent_call_penalty` | −0.15 for every selected agent |

`total_reward` is the sum of those five components. The values are fixed illustrative project weights. No health-improvement, recommendation-consistency, or conflict component is included: selecting agents here does not produce a measured next-month outcome, and the project has no validated conflict definition yet.

| Agent | Relevant when | Additional critical condition |
| --- | --- | --- |
| Budget | Always | Negative scheduled cash flow, unfunded expenses, observed income at or below 60% of base income, or a recent income drop of at least 30% |
| Debt | Debt balance or scheduled EMI exists | Missed payment, scheduled EMI at least 20% of current income, or debt with an unavailable payment ratio |
| Emergency fund | Always | Reserve coverage is below three months of scheduled expenses, or below six months when configured income volatility is at least 25% or income is observed low |
| Goal planning | A goal exists | At least one goal has an unfinished target; the agent may still advise deferral under cash pressure |
| Risk | Always | Negative scheduled cash flow, unfunded expenses, missed payment, or configured income volatility of at least 25% |
| Investment readiness | Positive current surplus, positive expenses and horizon, reserve at or above the applicable target, no missed payment, no observed low income or recent drop of at least 30%, and no high or unavailable debt ratio | Never critical in this proxy |

The investment rule decides whether running an additional screening agent is rewarded by this proxy. It does not say whether a household should invest. A missing reserve ratio does not trigger a critical Emergency check; a missing ratio when debt exists does trigger a critical Debt check. Both choices are explicit, reviewable assumptions.

## Run a reproducible example

From the repository root in PowerShell:

```powershell
Set-Location backend
..\.venv\Scripts\python -m app.rl.dynamic_reward --synthetic-id 1 --months 3 --seed 4 --shocks --shock-probability 0.5 --selected budget investment
```

The read-only JSON reports the population and trajectory seeds, selected agents, each month's observed amounts and flags, all five reward components, and the checks behind the relevant and critical sets. With the current generator and these arguments, months 1–3 have incomes `90778.08`, `83643.31`, and `44470.22`; the same Budget + Investment selection scores `-3.05`, `-6.05`, and `-7.05` project points. Those numbers are generated by the command, not manually assigned outcomes. The later month has negative scheduled cash flow; Investment is outside the proxy's relevant set in all three months because reserve coverage stays below the target.

Use `--selected` to choose any nonempty set of the six agent IDs. `--income-volatility 0.4` overrides the experiment's configured volatility; `--shock-probability` controls event frequency when shocks are enabled. Add both `--goal-target 12000 --goal-months 6` to include one explicitly labelled example goal with no simulated contributions. Omit both to preserve the no-goal case. Identical arguments yield identical output. The command reads synthetic data only; it does not access PostgreSQL, an account, an API key, or an external model.
